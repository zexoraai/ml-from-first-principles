Eight papers, implemented from the equations.

Attention, GPT, LoRA, DPO, tiled attention, quantization, CLIP and DDPM — each built by hand, checked against independent oracles, and documented so the claims can be audited rather than taken on trust.

Every artefact carries a fidelity tier. Nothing here claims to reproduce a published result, because on the hardware described in Environment & method that is not achievable — and saying so is more useful than implying otherwise.

How to read the labels

One vocabulary, applied to everything. It exists to prevent the most common portfolio overclaim: implementing a mechanism and describing it as reproducing a paper.

Fidelity tiers. Every project page states which tier each of its claims sits at.
TierMeansThe claim it licenses
Tier E Mechanism implemented from the paper's equations and verified for correctness — numerical parity against an independent reference, gradient checks, structural invariants. “I implemented and verified mechanism X.”
Tier R Reduced-scale reproduction. The full method runs end to end on real data, far below the paper's scale. Trends may be compared qualitatively; absolute numbers may not. “At a fraction of the scale, the method behaves qualitatively as reported.”
Tier P Reproduction of published results: same dataset, same scale, metric within published error bars. “I reproduced the published result.” Not claimed anywhere in this portfolio.

The eight projects

Status reflects what has actually been built and run, updated as work lands. Projects are built in dependency order: 1 → 2 produce a base model that 3 → 4 adapt and align; 5 optimises the attention primitive; 6 compresses; 7 and 8 are independent architectures reusing the shared training and evidence infrastructure.

01 live demo

Encoder–decoder Transformer

Multi-head attention, sinusoidal positional encoding, layer normalization, residual wiring, position-wise feed-forward, padding and causal masks — all hand-written. No nn.Transformer, and that is enforced by a test, not a promise. Trained, with in-browser inference verified against PyTorch.

Vaswani et al. · arXiv:1706.03762v7

Tiled attention → Triton

Reference attention, then tiled attention with online softmax, then a Triton kernel. The first two run and are measured here. The kernel is authored here but cannot be executed — there is no CUDA device — so no timings for it will be published until it actually runs.

Post-training quantization

An INT8 affine baseline, then one named PTQ method implemented faithfully. Careful to separate simulated quantization from packed low-bit storage from actual low-bit compute — three different claims that often get conflated.

What this site will not do

Commitments
  • No fabricated metrics. Every number on every page traces to a run identifier in the evidence register, with seeds, hardware, dataset version and a reproduction command.
  • No animation presented as a running kernel or a trained model. Live inference, cached output, prerecorded runs and conceptual visualisations are each labelled as such.
  • No invented URLs. A project links to a demo only once that demo has been deployed and tested.
  • Failures stay published. The evidence register keeps a benchmark that was wrong by 300×, because deleting it would remove the most useful lesson in it.

Build status, plainly

This portfolio is under active construction and the status pills above are accurate as of the last commit. Project 1's mechanisms are implemented and verified; no model has been trained yet, so no demo is live yet. When a demo appears, it will run genuine model weights in your browser and say so.

The Environment & method page is complete and worth reading first — it covers the measured hardware, two blockers that reshaped the whole plan, and a worked example of a benchmark that lied.
