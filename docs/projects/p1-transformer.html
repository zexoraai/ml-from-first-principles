Tier E — mechanisms Tier R — trained model checking parity…

Encoder–decoder Transformer, built from the equations

Every mechanism in Attention Is All You Need written by hand — scaled dot-product attention, multi-head projections, sinusoidal positional encoding, layer normalization, residual wiring, the position-wise feed-forward network, and both kinds of mask. No nn.Transformer, no nn.MultiheadAttention, no F.scaled_dot_product_attention, no nn.LayerNorm — and that is enforced by a test that walks the syntax tree, not by a promise in a README.

The research question

Can a sequence-to-sequence model learn to relocate and reformat information whose position varies from example to example, using attention alone and no recurrence?

The task is date normalisation. Given a human-written date in any of ten formats, emit ISO-8601: 

"March 3, 2019"          →  "2019-03-03"
"Sunday, 3 Mar 2019"     →  "2019-03-03"
"22nd December 1999"     →  "1999-12-22"
"2035 July 4"            →  "2035-07-04"

It is a deliberately easy task, chosen so that the mechanisms — not the difficulty — are what gets demonstrated. But it is not trivial in the way a copy task is. To emit output character 0 the model must locate the year, which may be at either end of the input. To emit character 5 it must find the month, which may be a word of three to nine letters or already a number. The mapping is a reordering, so a model without positional information cannot do it at all. That makes it a genuine test of cross-attention and positional encoding, with the convenient property that correctness is a string comparison and needs no judgement.

What is and is not claimed

The mechanisms are tier E: implemented from the equations and verified against independent oracles, gradient checks and structural invariants (161 tests). The trained model is tier R: a reduced-scale result on a synthetic task. There is no comparison here to the paper's WMT14 BLEU scores — that experiment was not attempted and is not attemptable on the hardware described in Environment & method.

Attention heads

Why these pictures are not explanations

An attention map shows where a weighted average drew from, in one head, at one layer, for one input. It does not establish that the information was used. A head can place high weight on a token and contribute nothing to the logit that actually decided the output: the residual stream carries information around it, later layers can overwrite it, and W^O can project its contribution into a direction the output projection ignores.

Establishing use requires intervention, not inspection — ablate the head and measure the change in the output, or patch its activations from a different input and see whether the prediction follows. Reading a heatmap and concluding “this head finds the year” is a hypothesis, not a result. None of the maps above are offered as evidence for a causal claim, and none of the numbers in the Results section depend on them.

Token probabilities at each decoding step

Greedy decoding takes the argmax at every step, so the distribution shown is exactly the one the chosen character came from. Entropy separates two failures that look identical in the output: confidently wrong (low entropy — it learned something wrong) from undecided (high entropy — it learned nothing here yet).

Architecture walkthrough

One forward pass for "3 Mar 2019" (10 characters), producing output position 0. Configuration: d_model=128, h=4, d_k=d_v=32, d_ff=512, 2 encoder + 2 decoder layers, post-norm.

  1. Tokenise

    Character level: 10 ids. Sub-word tokens would add a vocabulary-construction step with nothing to teach here, and would hide the digit-level copying that makes the attention maps legible. (1, 10)

  2. Embed, then scale by √d_model

    Section 3.4. The factor is √128 ≈ 11.31. Embeddings are initialised at std d_model^-0.5 ≈ 0.088; positional encodings are bounded in [-1, 1]. Skip the scaling and position drowns out token identity. (1, 10, 128)

  3. Add positional encoding

    Without it, self-attention is permutation-equivariant: shuffle the input and the output comes back shuffled with identical values. Nothing inside softmax(QKᵀ/√d_k)V depends on an index. A test demonstrates that weakness rather than asserting it, then shows it repaired.

  4. Encoder self-attention

    Project to q, k, v; split into 4 heads of 32; scores (1, 4, 10, 10); softmax over keys; weighted sum of values; merge heads; W^O. Then add the residual and normalise — post-norm, per §3.1.

  5. Position-wise feed-forward

    128 → 512 → ReLU → 128, applied to each position independently. This is the only place non-linear per-token computation happens, and it holds roughly twice the parameters of the attention sub-layer.

  6. Second encoder layer, then stop

    Output is the memory, (1, 10, 128). Every decoder layer will attend to this same tensor — decoder layer 0 does not read encoder layer 0. That is why the encoder is computed once and reused for all decoding steps.

  7. Decoder self-attention, masked

    With only [BOS] present the causal mask is vacuous, but it is still applied — at step 7 it will not be. Forbidden scores become -∞ so exp returns exactly zero.

  8. Cross-attention

    Queries from the decoder, keys and values from the memory. Scores (1, 4, 1, 10) — one row, ten columns. This is where the model decides which input characters matter for this output position. It is the only non-square score tensor in the model, and the one drawn by default in the viewer above.

  9. Project to logits

    (1, 1, 128) → (1, 1, 70) through the shared embedding matrix. Because weights are tied (§3.4), the logit for token t is the dot product of the hidden state with t's own embedding — literally “how much does my current state look like token t”.

  10. Argmax, append, repeat

    Back to step 7 with T = 2. The whole prefix is recomputed each step, so producing n tokens costs O(n²) decoder work. A KV cache would make it linear; it is deliberately not implemented, and no efficient-generation claim is made.

The full fourteen-step treatment — including the loss, gradient flow, checkpoint recovery, failure diagnosis and performance trade-offs — is in the teaching document, which also contains 30-second, five-minute and technical versions of the same explanation.

Equations wired to code

Every equation the paper states, and the function that implements it.

Attention(Q,K,V) = softmax(QKᵀ / √d_k) · V
§3.2.1, Equation 1
attention.scaled_dot_product_attention

The √d_k divisor is the paper's footnote-4 argument: with unit-variance components the dot product has variance d_k, so unscaled scores saturate softmax and the gradient vanishes. Measured, not asserted.

MultiHead(Q,K,V) = Concat(head₁…head_h)·W^O
head_i = Attention(QW_i^Q, KW_i^K, VW_i^V)
§3.2.2
attention.MultiHeadAttention, split_heads, merge_heads

One big matrix per role, sliced into heads — algebraically identical to the paper's h separate matrices, and far faster. Verified by copying our weights into nn.MultiheadAttention's packed layout and demanding identical output.

FFN(x) = max(0, xW₁ + b₁)W₂ + b₂
§3.3
layers.PositionwiseFeedForward

Biases are present because the paper writes them; the attention projections have none because it writes those as bare matrices.

y = LayerNorm(x + Dropout(Sublayer(x)))
§3.1 with dropout placed per §5.4
layers.SublayerConnection

This is post-norm, what the paper text says. The authors' own tensor2tensor release shipped pre-norm. Both are implemented; post-norm is the default because we cite §3.1.

LayerNorm(z) = (z − μ)/√(σ² + ε) ⊙ γ + β
Ba et al., arXiv:1607.06450
layers.LayerNorm

Two details must be right or parity breaks: σ² is biased (divide by n), and ε goes inside the square root. Both have dedicated tests that fail if “corrected”.

PE(pos,2i)  = sin(pos / 10000^(2i/d_model))
PE(pos,2i+1) = cos(pos / 10000^(2i/d_model))
§3.5
positional.sinusoidal_positional_encoding

The paper's stated reason for sinusoids: PE(pos+k) is a fixed linear function of PE(pos). A test verifies the rotation identity numerically, which is what makes relative addressing learnable from absolute encodings.

lrate = d_model^−0.5 · min(step^−0.5, step · warmup^−1.5)
§5.3, Equation 3
optim.NoamSchedule

The two branches are equal at step == warmup, so the peak sits exactly on the warmup step. Warmup is not decoration: post-norm rescales the identity path at every layer, and a large initial rate diverges without it.

q(correct) = 1 − ε  ·  q(other) = ε/(V−2)
§5.4, ε_ls = 0.1
optim.LabelSmoothingLoss

Padding gets zero smoothing mass — it is never a legitimate output. At ε = 0 this reduces exactly to cross-entropy, which is the cheapest strong check that the smoothed path has no normalisation error.

Metric definitions, before any values

  • cross-entropy — mean unsmoothed loss per non-padding target token, in nats. Unsmoothed on purpose: training uses label smoothing, which §5.4 says deliberately hurts perplexity, so the two must not share an axis.
  • token accuracy (teacher forced) — fraction of target positions whose argmax is correct given the correct prefix. The optimistic metric.
  • exact match (free running) — fraction of examples where greedy decoding from BOS alone, with no access to the target, reproduces the whole ISO string. The honest metric, and the headline. Strictly harder: one early slip derails everything after it.

The gap between the last two is the informative quantity. A wide gap means the model predicts well one step at a time but compounds its own errors once it consumes its own output.

Limitations and failures

Every failure the model makes on held-out data

At this accuracy a 24-example sample contains no failures at all, and “here are 24 correct outputs” would not be a failure analysis. So the full test split is scanned and every failure reported. The table is read from the evidence file.

What the failures have in common

All three are digit-level slips inside an otherwise perfectly structured output. The model never emits a malformed string: the YYYY-MM-DD skeleton, the hyphen positions and the field widths are always right. What fails is character selection.

Two of the three are the same error: a two-digit day of 30 or 31 emitted as 03 — the correct digits, in the wrong order, with the leading zero that a single-digit day would need. The third is 1966 → 1996, a 6/9 substitution.

That pattern is consistent with the division of labour the architecture implies. The structure is positional and comes cheaply from the decoder's own causal self-attention — it always knows it is at output position 8 and that position 8 is a day digit. The content requires cross-attention to fetch the right source character, and that is where the error lands. It is a hypothesis consistent with the evidence, not a demonstrated mechanism: confirming it would need the ablation work described in the attention caveat above.

What this project does not establish

  • No published result is reproduced. The paper's WMT14 English–German BLEU of 28.4 required 8×P100 for 12 hours. This ran on a 6-core mobile CPU with no GPU. That experiment was not attempted, and the trained model here says nothing about it.
  • The task is synthetic and easy. Ten formats, generated by our own code, with a single correct answer per input. High accuracy here is evidence the mechanisms work, not evidence of language ability.
  • Single run. One seed, no variance estimate. No claim rests on a difference small enough for seed noise to explain.
  • Attention maps are not explanations. See the box in the demo section. This is the most common overclaim in Transformer write-ups and none of the results here depend on avoiding it.
  • Greedy decoding only. The paper used beam search with beam 4 and length penalty 0.6. Beam search is not implemented.
  • No KV cache. Generation is O(n²) in output length. No efficiency claim is made.
  • Timings are lower bounds. The development machine runs an unrelated 37-container stack, which varied measured throughput by up to 14×. See Environment & method.

Known data quirk, documented rather than hidden

May is the only month whose three-letter abbreviation equals its full name, so two pairs of renderers produce byte-identical strings for May dates ("May 1, 2019" from both month_day_year and abbr_day_year). May dates therefore have 8 distinct renderings where other months have 10. This was found by a test, not by inspection, and the generator now deduplicates on the rendered string rather than trusting distinct format names. An earlier collision ("24 Sep 1984" from two different renderers, for every two-digit day) silently duplicated examples until the same test caught it.

Case study

1 · Research question

Can attention alone, with no recurrence, learn to relocate and reformat information whose position varies per example?

2 · Hypothesis

A two-layer encoder–decoder with 4 heads and d_model=128 should reach high exact-match on date normalisation within a few thousand CPU-minutes, and its cross-attention should concentrate on the input span corresponding to each output field. The second half of that hypothesis is a prediction about a picture, and is treated as unverified — see the caveat in the demo section.

3 · What was implemented

All seven mechanisms by hand, plus the §5.3 schedule and §5.4 label smoothing, the data generator, a resumable training loop, greedy decoding, an ONNX-free JavaScript inference engine, and a parity harness tying the two together. The paper's post-norm placement is the default, with pre-norm behind a flag so the discrepancy between the paper and the authors' code is a runnable experiment rather than a footnote.

4 · Experimental setup

Splits are drawn over calendar dates, not rendered strings, so every rendering of a date lands in one split. The naive alternative leaks badly: the model would meet "March 3, 2019" in training and be scored on "3 Mar 2019" having already memorised that date's answer, and validation accuracy would measure memorisation while looking excellent. A test asserts no ISO date appears in two splits.

5 · Baseline

An untrained model of the same architecture. Its loss sits at approximately log(V) = log(70) ≈ 4.25 nats — a uniform distribution over the vocabulary — and its exact-match is 0%. A test pins the initialisation to that value, because an init that is accidentally informative would flatter every subsequent number.

6 · Measured results

See the Results section, read live from the evidence file.

7 · Failures and revisions

Four worth recording, all found by tests rather than by inspection:

  • A benchmark wrong by 300×. The first CPU benchmark timed one call per sample and reported a 0.53 M-parameter training step at 4,980 ms — while simultaneously reporting a 27 M-parameter step at 1,147 ms. A larger model cannot be faster. Reading that as “this laptop is slow” would have baked a ~50× error into every compute estimate for all eight projects. The bad run is kept in the register, marked invalid.
  • Two renderer collisions. Described above. The second one is a fact about English month names and cannot be fixed by changing formats, which is why deduplication moved to the rendered string.
  • A test that was wrong about the model. An early padding test replaced pad ids with a real token id and expected the output to be unchanged. But the padding mask is derived from the ids, so that legitimately changes the mask. The test failed and the model was right; the correct formulation compares padded against unpadded, and is strictly stronger.
  • A resume bug PyTorch does not warn about. LRScheduler.load_state_dict restores the scheduler's position but does not write the learning rate back into optimizer.param_groups. Real resume code survives only because the optimizer's own state dict carries the lr — making correctness depend on the order of two calls. The training script now syncs explicitly.

8 · What the evidence supports

That the mechanisms are implemented correctly — numerical parity against two independent PyTorch oracles and a float64 hand transcription, interventional proof that masking blocks information flow end-to-end through the full stack, and a single-batch overfit that reaches near-zero loss and exact greedy reconstruction. And that at this scale the architecture learns the task from date-disjoint data.

9 · What remains unproven

Everything about scale, natural language, and interpretability. Whether the attention patterns mean what they appear to mean is untested — that needs ablation or activation patching, neither of which was run. Whether post-norm or pre-norm is better here is unmeasured; the comparison is set up in the mastery pack as a prediction exercise, not reported as a result.

Reproduce it

All Python runs inside a pinned Linux container. That is not a stylistic choice — the development host has Windows Smart App Control enforcing, which blocks PyTorch's unsigned DLLs from loading. Full story here. 

git clone https://github.com/zexoraai/ml-from-first-principles
cd ml-from-first-principles
docker build -t ml-labs:cpu .

# correctness suite — every mechanism, plus the no-shortcuts check
.\run.cmd python -m pytest tests -q

# train (about 30 min on 6 CPU threads; 2 threads is the measured optimum)
.\run.cmd python scripts/train_p1.py --run-name p1-date-post-6k --steps 6000 --warmup 400

# export the trained weights for in-browser inference, with a parity fixture
.\run.cmd python scripts/export_p1_web.py --checkpoint runs/p1-date-post-6k/checkpoint_best.pt

Three explanations, three depths

30 seconds

A Transformer turns one sequence into another by letting every output position look directly at every input position and take a weighted average of what it finds — with the model choosing the weights. Doing that in several “heads” at once lets it track several kinds of relationship simultaneously. Because nothing waits for anything else, the whole thing trains in parallel, which is why it replaced recurrent networks.

Five minutes

Every position emits a key (“what I am”), a value (“what I'd contribute”) and a query (“what I need”). Dot a query against all keys, softmax, and you have weights summing to one; take the weighted average of the values. Divide by √d_k or high-dimensional dot products saturate the softmax and kill the gradient. Do it h times on narrower slices. Then note that nothing so far depends on position — so add a sinusoidal pattern, chosen because shifting position by k rotates each sine/cosine pair by a fixed angle, making “look three back” one learnable linear map. Stack it, mask the decoder's future, and feed it the target shifted right: one pass then trains every next-token prediction at once. Full version.
